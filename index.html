🔍 Búsqueda Lineal

El algoritmo de búsqueda más simple: revisa cada elemento uno por uno

Array Interactivo

▶ 📋 Pseudocódigo Búsqueda Lineal

funcion BusquedaLineal(array, objetivo):
    para i desde 0 hasta longitud(array) - 1:
        si array[i] == objetivo:
            retornar i  // Elemento encontrado en posición i
    
    retornar -1  // Elemento no encontrado

Complejidad: O(n) - En el peor caso, debe revisar todos los elementos.

Sobre Búsqueda Lineal:

El algoritmo más simple. Revisa cada elemento secuencialmente hasta encontrar el objetivo o llegar al final.

✅ Ventajas:
  • Muy simple de implementar
  • Funciona en datos no ordenados
  • No requiere preprocesamiento
❌ Desventajas:
  • O(n) - lento para datos grandes
  • Revisa todos los elementos en peor caso
  • Ineficiente comparado con búsqueda binaria

🎯 Búsqueda Binaria

Búsqueda eficiente en arrays ordenados mediante división y conquista

Array Ordenado

▶ 📋 Pseudocódigo Búsqueda Binaria

funcion BusquedaBinaria(array_ordenado, objetivo):
    izquierda = 0
    derecha = longitud(array_ordenado) - 1
    
    mientras izquierda <= derecha:
        medio = (izquierda + derecha) / 2
        
        si array_ordenado[medio] == objetivo:
            retornar medio  // Encontrado
        
        si array_ordenado[medio] < objetivo:
            izquierda = medio + 1  // Buscar en mitad derecha
        sino:
            derecha = medio - 1    // Buscar en mitad izquierda
    
    retornar -1  // No encontrado

Complejidad: O(log n) - Divide el espacio de búsqueda a la mitad en cada paso. Requiere array ordenado.

Sobre Búsqueda Binaria:

Mucho más eficiente que la búsqueda lineal, pero requiere que el array esté ordenado. Divide el espacio de búsqueda a la mitad en cada paso.

✅ Ventajas:
  • O(log n) - muy rápido
  • Eficiente para datos grandes
  • Reduce espacio de búsqueda a la mitad
❌ Desventajas:
  • Requiere datos ordenados
  • No funciona con listas enlazadas
  • Necesita acceso aleatorio rápido

🫧 Bubble Sort (Burbuja)

El algoritmo más simple: compara pares adyacentes y los intercambia si están en orden incorrecto

Array a Ordenar

▶ 📋 Pseudocódigo Bubble Sort

funcion BubbleSort(array):
    n = longitud(array)
    
    para i desde 0 hasta n - 1:
        intercambiado = falso
        
        para j desde 0 hasta n - i - 2:
            si array[j] > array[j + 1]:
                // Intercambiar elementos
                temp = array[j]
                array[j] = array[j + 1]
                array[j + 1] = temp
                intercambiado = verdadero
        
        // Si no hubo intercambios, ya está ordenado
        si no intercambiado:
            romper
    
    retornar array

Complejidad: O(n²) - Los elementos más grandes "burbujean" hacia el final en cada pasada.

Sobre Bubble Sort:

Simple pero ineficiente para arrays grandes. Útil para aprender los conceptos básicos de ordenamiento.

✅ Ventajas:
  • Muy fácil de entender e implementar
  • No requiere memoria adicional (in-place)
  • Algoritmo estable
❌ Desventajas:
  • O(n²) - muy lento para datos grandes
  • Hace muchas comparaciones innecesarias
  • Raramente usado en producción

🎯 Selection Sort (Selección)

Encuentra el mínimo y lo coloca en su posición correcta en cada iteración

Array a Ordenar

▶ 📋 Pseudocódigo Selection Sort

funcion SelectionSort(array):
    n = longitud(array)
    
    para i desde 0 hasta n - 2:
        // Encontrar el índice del mínimo
        indice_minimo = i
        
        para j desde i + 1 hasta n - 1:
            si array[j] < array[indice_minimo]:
                indice_minimo = j
        
        // Intercambiar el mínimo con el elemento actual
        si indice_minimo != i:
            temp = array[i]
            array[i] = array[indice_minimo]
            array[indice_minimo] = temp
    
    retornar array

Complejidad: O(n²) - Hace menos intercambios que Bubble Sort.

Sobre Selection Sort:

Encuentra el elemento más pequeño y lo coloca en su posición final. Más eficiente en intercambios que Bubble Sort.

✅ Ventajas:
  • Fácil de implementar
  • Hace mínimos intercambios (O(n))
  • Funciona bien con escrituras costosas
❌ Desventajas:
  • O(n²) incluso en mejor caso
  • No es estable
  • No aprovecha datos parcialmente ordenados

📥 Insertion Sort (Inserción)

Construye el array ordenado insertando elementos uno por uno en su posición correcta

Array a Ordenar

▶ 📋 Pseudocódigo Insertion Sort

funcion InsertionSort(array):
    n = longitud(array)
    
    para i desde 1 hasta n - 1:
        clave = array[i]
        j = i - 1
        
        // Mover elementos mayores que clave una posición adelante
        mientras j >= 0 y array[j] > clave:
            array[j + 1] = array[j]
            j = j - 1
        
        // Insertar clave en su posición correcta
        array[j + 1] = clave
    
    retornar array

Complejidad: O(n²) peor caso, O(n) mejor caso - Muy eficiente para arrays pequeños o casi ordenados.

Sobre Insertion Sort:

Como ordenar cartas en tu mano. Eficiente para arrays pequeños y datos casi ordenados.

✅ Ventajas:
  • O(n) en mejor caso (datos ordenados)
  • Muy eficiente para arrays pequeños
  • Algoritmo estable y adaptativo
  • Funciona bien online (datos en streaming)
❌ Desventajas:
  • O(n²) en peor caso
  • Ineficiente para arrays grandes
  • Muchos desplazamientos de elementos

🔀 Merge Sort (Mezcla)

Divide y conquista: divide el array recursivamente y luego fusiona las partes ordenadas

Array a Ordenar

▶ 📋 Pseudocódigo Merge Sort

funcion MergeSort(array, inicio, fin):
    si inicio < fin:
        medio = (inicio + fin) / 2
        
        // Dividir recursivamente
        MergeSort(array, inicio, medio)
        MergeSort(array, medio + 1, fin)
        
        // Fusionar las mitades ordenadas
        Merge(array, inicio, medio, fin)

funcion Merge(array, inicio, medio, fin):
    // Crear arrays temporales
    izquierda = array[inicio...medio]
    derecha = array[medio+1...fin]
    
    i = 0, j = 0, k = inicio
    
    // Fusionar comparando elementos
    mientras i < longitud(izquierda) y j < longitud(derecha):
        si izquierda[i] <= derecha[j]:
            array[k] = izquierda[i]
            i++
        sino:
            array[k] = derecha[j]
            j++
        k++
    
    // Copiar elementos restantes
    copiar resto de izquierda y derecha a array

Complejidad: O(n log n) siempre - Divide el problema a la mitad recursivamente.

Sobre Merge Sort:

Algoritmo de divide y conquista. Divide el array recursivamente y fusiona las partes ordenadas.

✅ Ventajas:
  • O(n log n) garantizado
  • Algoritmo estable
  • Predecible y confiable
  • Funciona bien con datos grandes
❌ Desventajas:
  • Requiere O(n) memoria extra
  • No es in-place
  • Más lento que Quick Sort en promedio

⚡ Quick Sort (Rápido)

Elige un pivot y particiona el array: menores a la izquierda, mayores a la derecha

Array a Ordenar

▶ 📋 Pseudocódigo Quick Sort

funcion QuickSort(array, inicio, fin):
    si inicio < fin:
        // Particionar y obtener índice del pivot
        pivotIndex = Partition(array, inicio, fin)
        
        // Ordenar recursivamente las dos mitades
        QuickSort(array, inicio, pivotIndex - 1)
        QuickSort(array, pivotIndex + 1, fin)

funcion Partition(array, inicio, fin):
    pivot = array[fin]  // Elegir último elemento como pivot
    i = inicio - 1
    
    para j desde inicio hasta fin - 1:
        si array[j] <= pivot:
            i++
            intercambiar array[i] con array[j]
    
    // Colocar pivot en su posición final
    intercambiar array[i + 1] con array[fin]
    retornar i + 1

Complejidad: O(n log n) promedio, O(n²) peor caso - El más rápido en la práctica.

Sobre Quick Sort:

Uno de los algoritmos más rápidos en la práctica. Usa particionamiento recursivo alrededor de un pivot.

✅ Ventajas:
  • Muy rápido en promedio
  • In-place (poca memoria extra)
  • Buen rendimiento en caché
  • Usado en bibliotecas estándar
❌ Desventajas:
  • O(n²) en peor caso
  • No es estable
  • Sensible a elección de pivot
  • Recursión profunda posible

▶ 📋 Pseudocódigo A*

funcion A_Estrella(inicio, objetivo):
    abiertos = [inicio]              // Nodos por explorar
    cerrados = []                    // Nodos ya visitados
    
    g[inicio] = 0                    // Costo desde inicio
    f[inicio] = heuristica(inicio, objetivo)  // Estimación total
    
    mientras abiertos no esté vacío:
        actual = nodo con menor f en abiertos
        
        si actual == objetivo:
            retornar reconstruir_camino(actual)
        
        mover actual de abiertos a cerrados
        
        para cada vecino de actual:
            si vecino en cerrados:
                continuar
            
            g_tentativo = g[actual] + distancia(actual, vecino)
            
            si vecino no en abiertos:
                agregar vecino a abiertos
            sino si g_tentativo >= g[vecino]:
                continuar  // No es mejor camino
            
            // Este es el mejor camino hasta ahora
            padre[vecino] = actual
            g[vecino] = g_tentativo
            f[vecino] = g[vecino] + heuristica(vecino, objetivo)
    
    retornar "No hay camino"

Clave: La heurística (distancia Manhattan) guía la búsqueda hacia el objetivo, haciendo que A* sea más eficiente que Dijkstra.

⛰️ Hill Climbing

Optimización por búsqueda local ascendente

Superficie de Optimización

▶ 📋 Pseudocódigo Hill Climbing

funcion HillClimbing(funcion_objetivo, max_iteraciones):
    actual = solución_aleatoria()   // Punto de partida
    valor_actual = evaluar(actual)
    
    para i desde 1 hasta max_iteraciones:
        vecinos = generar_vecinos(actual)  // Soluciones cercanas
        
        mejor_vecino = null
        mejor_valor = valor_actual
        
        // Buscar el mejor vecino
        para cada vecino en vecinos:
            valor_vecino = evaluar(vecino)
            
            si valor_vecino > mejor_valor:
                mejor_vecino = vecino
                mejor_valor = valor_vecino
        
        // Si no hay mejora, hemos llegado a un máximo local
        si mejor_valor <= valor_actual:
            romper  // Terminar búsqueda
        
        // Moverse al mejor vecino
        actual = mejor_vecino
        valor_actual = mejor_valor
    
    retornar actual, valor_actual

Limitación: Siempre sube, nunca baja. Puede quedar atrapado en máximos locales sin encontrar el óptimo global.

Sobre Hill Climbing:

Algoritmo de optimización que siempre se mueve hacia la mejor solución vecina. Puede quedar atrapado en máximos locales.

"La ambición de siempre subir puede cegarte ante caminos mejores que requieren primero descender." - "Paradoja de la optimización local"

🔥 Simulated Annealing

Optimización probabilística inspirada en el recocido metalúrgico

Exploración del Espacio de Búsqueda

▶ 📋 Pseudocódigo Simulated Annealing

funcion SimulatedAnnealing(temp_inicial, tasa_enfriamiento, max_iter):
    actual = solución_aleatoria()
    mejor = actual
    temperatura = temp_inicial
    
    para i desde 1 hasta max_iter:
        vecino = generar_vecino_aleatorio(actual)
        
        delta = evaluar(vecino) - evaluar(actual)
        
        // Aceptar si es mejor O con cierta probabilidad si es peor
        si delta > 0:  // Mejor solución
            actual = vecino
            si evaluar(vecino) > evaluar(mejor):
                mejor = vecino
        
        sino:  // Peor solución
            probabilidad = exp(delta / temperatura)
            
            si random() < probabilidad:
                actual = vecino  // Aceptar empeoramiento
        
        // Enfriar gradualmente
        temperatura = temperatura * tasa_enfriamiento
    
    retornar mejor

Ventaja: La aceptación probabilística de soluciones peores permite escapar de máximos locales. La temperatura controla cuánta "exploración" vs "explotación".

Sobre Simulated Annealing:

Acepta soluciones peores con cierta probabilidad que disminuye con el tiempo, permitiendo escapar de máximos locales.

"A veces, retroceder un paso te permite saltar más lejos. La aleatoriedad controlada es sabiduría disfrazada." - "Principio del recocido simulado"

🧬 Algoritmos Genéticos

Optimización evolutiva inspirada en la selección natural

Evolución de la Población

▶ 📋 Pseudocódigo Algoritmos Genéticos

funcion AlgoritmoGenetico(tam_poblacion, generaciones, tasa_mutacion, tasa_crossover):
    poblacion = generar_poblacion_inicial(tam_poblacion)
    evaluar_fitness(poblacion)
    
    para g desde 1 hasta generaciones:
        nueva_poblacion = []
        
        // Elitismo: mantener el mejor individuo
        mejor = individuo_con_mayor_fitness(poblacion)
        nueva_poblacion.agregar(mejor)
        
        // Generar nueva población
        mientras tamaño(nueva_poblacion) < tam_poblacion:
            // Selección por torneo
            padre1 = seleccion_torneo(poblacion)
            padre2 = seleccion_torneo(poblacion)
            
            // Crossover (cruce)
            si random() < tasa_crossover:
                hijo = crossover(padre1, padre2)
            sino:
                hijo = padre1
            
            // Mutación
            si random() < tasa_mutacion:
                hijo = mutar(hijo)
            
            nueva_poblacion.agregar(hijo)
        
        poblacion = nueva_poblacion
        evaluar_fitness(poblacion)
    
    retornar individuo_con_mayor_fitness(poblacion)

funcion seleccion_torneo(poblacion):
    // Seleccionar k individuos aleatorios y retornar el mejor
    competidores = seleccionar_aleatorios(poblacion, k=3)
    retornar mejor_de(competidores)

funcion crossover(padre1, padre2):
    // Crossover aritmético (promedio ponderado)
    alpha = random()
    hijo = alpha * padre1 + (1 - alpha) * padre2
    retornar hijo

funcion mutar(individuo):
    // Mutación gaussiana
    individuo = individuo + random_gaussiano(0, sigma)
    retornar individuo

Clave: La combinación de selección (los mejores sobreviven), crossover (mezcla de características) y mutación (exploración aleatoria) permite encontrar soluciones óptimas sin quedar atrapado en máximos locales.

Sobre Algoritmos Genéticos:

Inspirados en la evolución biológica, estos algoritmos mantienen una población de soluciones que evoluciona mediante selección, cruce y mutación.

"La naturaleza no busca la perfección en un solo intento, sino que evoluciona generación tras generación. Así también optimizamos." - "Principio de la evolución artificial"

🐦 Particle Swarm Optimization

Optimización basada en el comportamiento de enjambres

Movimiento del Enjambre

▶ 📋 Pseudocódigo PSO

funcion ParticleSwarmOptimization(num_particulas, max_iteraciones):
    // Inicializar enjambre
    para cada particula i:
        posicion[i] = random()
        velocidad[i] = random()
        mejor_personal[i] = posicion[i]
    
    mejor_global = particula_con_mejor_fitness()
    
    para iter desde 1 hasta max_iteraciones:
        para cada particula i:
            // Actualizar velocidad
            componente_cognitivo = c1 * random() * (mejor_personal[i] - posicion[i])
            componente_social = c2 * random() * (mejor_global - posicion[i])
            inercia = w * velocidad[i]
            
            velocidad[i] = inercia + componente_cognitivo + componente_social
            
            // Actualizar posición
            posicion[i] = posicion[i] + velocidad[i]
            
            // Actualizar mejor personal
            si fitness(posicion[i]) > fitness(mejor_personal[i]):
                mejor_personal[i] = posicion[i]
            
            // Actualizar mejor global
            si fitness(posicion[i]) > fitness(mejor_global):
                mejor_global = posicion[i]
    
    retornar mejor_global

Clave: Cada partícula se mueve influenciada por su mejor posición histórica (componente cognitivo) y la mejor posición global del enjambre (componente social). La inercia mantiene la dirección previa.

Sobre PSO:

Inspirado en el comportamiento social de bandadas de pájaros. Las partículas se mueven influenciadas por su experiencia personal y la del grupo.

"La sabiduría del enjambre supera la del individuo. Juntos encontramos lo que solos no podríamos." - "Inteligencia colectiva"

🎨 K-means Clustering

Agrupamiento de datos en K clusters mediante iteración y refinamiento

Espacio de Datos 2D

Cluster 1 Cluster 2 Cluster 3 Cluster 4 Cluster 5 ⭐ Centroides

▶ 📋 Pseudocódigo K-means

funcion KMeans(puntos, K, max_iteraciones):
    // 1. Inicialización: seleccionar K centroides aleatorios
    centroides = seleccionar_K_puntos_aleatorios(puntos, K)
    
    para iter desde 1 hasta max_iteraciones:
        // 2. Asignación: asignar cada punto al centroide más cercano
        para cada punto en puntos:
            distancias = []
            
            para cada centroide en centroides:
                distancia = distancia_euclidiana(punto, centroide)
                distancias.agregar(distancia)
            
            // Asignar al cluster del centroide más cercano
            punto.cluster = indice_del_minimo(distancias)
        
        // 3. Actualización: recalcular centroides
        nuevos_centroides = []
        
        para k desde 0 hasta K - 1:
            puntos_del_cluster = filtrar(puntos, cluster == k)
            
            si puntos_del_cluster no está vacío:
                // Centroide = promedio de todos los puntos del cluster
                nuevo_x = promedio([p.x para p en puntos_del_cluster])
                nuevo_y = promedio([p.y para p en puntos_del_cluster])
                nuevos_centroides.agregar({x: nuevo_x, y: nuevo_y})
            sino:
                // Mantener centroide anterior si cluster vacío
                nuevos_centroides.agregar(centroides[k])
        
        // 4. Verificar convergencia
        si centroides == nuevos_centroides:
            romper  // Algoritmo ha convergido
        
        centroides = nuevos_centroides
    
    retornar centroides, asignaciones

funcion distancia_euclidiana(p1, p2):
    retornar sqrt((p1.x - p2.x)² + (p1.y - p2.y)²)

Complejidad: O(n × K × i) donde n = número de puntos, K = número de clusters, i = iteraciones. El algoritmo converge cuando los centroides dejan de moverse.

Sobre K-means:

Algoritmo de clustering que agrupa datos en K clusters. Itera entre asignar puntos al centroide más cercano y recalcular centroides hasta convergencia.

✅ Ventajas:
  • Simple y fácil de implementar
  • Escala bien a grandes datasets
  • Converge rápidamente
  • Funciona bien con clusters esféricos
❌ Desventajas:
  • Requiere especificar K de antemano
  • Sensible a inicialización
  • Puede quedar en mínimos locales
  • No funciona bien con clusters no esféricos
"Los patrones emergen cuando dejamos que los datos hablen por sí mismos." - "Aprendizaje no supervisado"
